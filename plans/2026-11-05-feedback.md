# Send Feedback and the Repository Link Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Settings → About gets "Send Feedback…" (an email to the developer with the diagnostics, routed by the default mail app) and "Open on GitHub ↗".

**Architecture:** A pure `FeedbackMail` builds the body, the `mailto:` URL and the route; a `FeedbackSender` (@Observable, MainActor) runs the route through a `FeedbackSystem` protocol wrapping NSWorkspace, NSSharingService and NSPasteboard, so it is tested with a fake. The Settings view adds two rows and a status line.

**Tech Stack:** Swift 6, SwiftUI, AppKit (NSWorkspace, NSSharingService, NSPasteboard), Swift Testing.

**Spec:** `specs/2026-11-05-feedback-design.md`

## Global Constraints

- Address `andreu.puzikov.21@gmail.com`, subject `Workdeck feedback`, repository `https://github.com/LuckyWins/Workdeck`, file name `Workdeck-diagnostics.txt` (0600, in the app's temporary folder).
- Body exactly as spec §2.1 step 5 (version `HelperConstants.version(of: .main)` gives "1.1.5 (7)"; macOS as `ProcessInfo.processInfo.operatingSystemVersion` "major.minor.patch"; model `sysctlbyname("hw.model")`, identifier only).
- Routes: Mail (`com.apple.mail`) and the sharing service can perform → compose with attachment; another handler or Mail unable → mailto + reveal in Finder + report on clipboard + status "Attach Workdeck-diagnostics.txt from Finder, or paste the diagnostics into the email."; no handler → clipboard "<address>\n\n<report>" + status "No mail app is set up. The address and the diagnostics are on the clipboard."; status clears after ~8 s.
- The report is the existing Copy Diagnostics text (last hour of log, off the main thread). Footer sentence as spec §2.3.
- No commits until the user says "коммить". Suites: `xcodebuild -scheme Workdeck -destination 'platform=macOS' test -only-testing:WorkdeckTests/<Suite> 2>&1 | grep -E "error:|recorded an issue|Test run with|\*\* TEST"`.

## Review Focus

- **A body with `&`, `?`, `#`, `+` and newlines survives the `mailto:` URL.** Pinned in Task 1 by `mailtoKeepsEveryCharacter`.
- **Nothing is sent by Workdeck itself:** every route only opens or copies. Pinned in Task 2 by the fake recording only open/compose/reveal/copy calls.
- **No mail app at all does not fail silently.** Pinned in Task 2 by `noMailAppPutsAddressAndReportOnTheClipboard`.

### Task 2: Sending

**Files:** Create `Workdeck/Core/Feedback/FeedbackSender.swift`; Test `WorkdeckTests/FeedbackSenderTests.swift` (fake `FeedbackSystem` in the test file or Fakes)

**Interfaces — Produces:**
```swift
@MainActor protocol FeedbackSystem {
    func defaultMailApp() -> String?          // bundle id of the mailto: handler
    func mailCanCompose(items: [Any]) -> Bool
    func composeMail(recipients: [String], subject: String, items: [Any])
    func open(_ url: URL)
    func reveal(_ file: URL)
    func copy(_ text: String)
}
@Observable @MainActor final class FeedbackSender {
    init(system: any FeedbackSystem, folder: URL, report: @escaping @Sendable () async -> String, appVersion: String, macOS: String, model: String, clearAfter: Duration = .seconds(8))
    private(set) var isPreparing: Bool
    private(set) var status: String?
    func send() async
}
```
- [ ] Tests: `mailComposesWithTheReportAttached` (file written 0600 with the report, compose called with the address, subject, body and the file URL; nothing opened); `anotherMailAppOpensMailtoAndShowsTheFile` (open(mailto), reveal(file), copy(report), status as spec); `noMailAppPutsAddressAndReportOnTheClipboard`; `theStatusClears` (clearAfter .zero). Run → FAIL; implement (a `SystemFeedbackSystem` with NSWorkspace `urlForApplication(toOpen:)` → `Bundle(url:)?.bundleIdentifier`, `NSSharingService(named: .composeEmail)`, `activateFileViewerSelecting`, NSPasteboard); run → PASS.
