# CLAUDE.md

Guidance for AI coding agents working in this repository.

## Project

Workdeck is a macOS menu bar toolbox for developers. Each tool is one row in the popover and lives in its own folder under `Workdeck/Features/`. The first tool is Closed-Lid Mode, which keeps the Mac awake while the lid is closed.

## Build and Test

- Shortcuts: `make build` (Release into `./build`), `make test`, `make install` (copies to `/Applications`), `make clean`, `make screenshots` (renders the README and landing page images from demo data into `docs/media/screenshots/`, then compresses the notch animations losslessly with `oxipng`: `brew install oxipng`), `make release-prep VERSION=x.y.z` (moves `CHANGELOG.md`'s Unreleased under the version, bumps `MARKETING_VERSION` and the build number, commits; see `docs/releasing.md`). Release scripts: `scripts/release/`, tests `python3 -I scripts/release/test_release.py` and `python3 -I scripts/release/test_install.py` (the install script).
- Build: `xcodebuild -scheme Workdeck -destination 'platform=macOS' build`
- Test: `xcodebuild -scheme Workdeck -destination 'platform=macOS' test 2>&1 | grep -E "error:|recorded an issue|Test run with|\*\* TEST"` (`-quiet` hides Swift Testing output)
- Single suite: add `-only-testing:WorkdeckTests/<SuiteName>` after `test`.
- Tests use Swift Testing and are hosted in `Workdeck.app`. Test `UserDefaults` come from `makeTestDefaults()` (a suite in a temporary folder; a named suite would leave a plist in `~/Library/Preferences`, and `TestDefaultsTests` refuses one). `AppDelegate` skips its startup helper refresh when `XCTestConfigurationFilePath` is set, so tests never talk to the real privileged helper.
- Helper logs: `/usr/bin/log stream --predicate 'subsystem == "com.appcreators.workdeck.helper"'`.

## Architecture

- `Workdeck/` — the menu bar app: SwiftUI, unsandboxed, `MainActor` default actor isolation.
  - `App/` scenes and top-level views; `Core/` helper client, helper installer, settings; `Features/<Tool>/` per-tool logic and views.
- `WorkdeckHelper/` — privileged launchd daemon running as root (no default actor isolation). Registered with `SMAppService.daemon`, reached over XPC.
- `Shared/` — compiled into both targets: the XPC protocol and constants. Types here must be explicitly `nonisolated`.
- `LaunchDaemons/` — launchd job copied into `Workdeck.app/Contents/Library/LaunchDaemons`.
- `site/` — the landing page (`index.html`, static, nothing from third parties) and `install.sh` (the one install path: reads the Sparkle appcast, checks the team signature, quits a running Workdeck with SIGTERM like `make install`, swaps the app in; no `sudo`), published to `luckywins.github.io/Workdeck` by `.github/workflows/pages.yml` on an Ubuntu runner with `docs/media/icon.png` copied in.
- `WorkdeckStatusLine/` — `workdeck-statusline`, the Claude Code status line command embedded in `Contents/Helpers`. Only `main.swift`; its logic is `StatusLineRunner` in `ClaudeUsage/`. It must always exit 0 and stay fast (it runs on every Claude Code message).
- `WorkdeckHook/` — `workdeck-hook`, the Claude Code hook command embedded in `Contents/Helpers`. Only `main.swift`; its logic is `HookRunner` in `ClaudeHooks/`. It must always exit 0, print nothing, stay fast (it runs on every tool call), and never store prompts or answers: `HookPayloadFilter` is an allowlist, and from tool input it keeps only `action(toolName:input:)`'s 30-character summary and an edit's file name, from an edit's tool response only `lineCounts(toolName:response:)`, plus the tool call ID. With `--agent codex` it is Codex's hook: events go to `sessions-codex/`, Codex's `PermissionRequest` and `Interrupt` are understood, and only the `codex` PID, the agent's `model` on `SubagentStart`, a spawn's `task_name`, and an applied `apply_patch`'s counts and file names (`CodexPatchText`) are added.
- `ClaudeHooks/` — compiled into the app and `WorkdeckHook` (not the privileged helper): hook event model, payload filter, per-session event files. Everything here is `nonisolated`.
- `Workdeck/Features/ClaudeCode/` — the Claude Code tool. `ClaudeCodeController` composes `Limits/` (`ClaudeLimitsController`: status line, usage API, limit alerts) and `Sessions/` (`ClaudeSessionsController`: session hooks, store and reducer, alerts, keep-awake, window activation) into its popover row and its part of the notch; settings live at the folder root. Claude Code sends no hook on Esc or a denied permission, so `TranscriptInterruptReader` reads the tail of a quiet busy session's transcript for the `[Request interrupted by user` line and the store adds an `Interrupt` event in memory; only that line's time is decoded, never text.
- `Workdeck/Features/Notch/` — the notch every agent tool shares: `NotchPresenter` (DynamicNotchKit), the notch views, `LimitsPresentation`, flashes, peek and countdown. `NotchComposer` owns the presenter and decides what shows; each agent tool conforms to `AgentSource` and hands it an `AgentNotchPart`. `NotchSettings` holds the settings every agent shares (Settings → Notch) under the keys Claude Code's settings used. Without a display that has a camera housing, `NotchPresenter` draws a virtual notch on the main display (DynamicNotchKit's `.notch` style on a plain screen) unless the "Without a notch" setting picks the menu bar text.
- `Workdeck/Features/ClaudeCode/Instances/` and `Chats/` — extra Claude Code instances (`CLAUDE_CONFIG_DIR`, a `~/.zshrc` alias, sign-in through a Terminal `.command` script) and the Chats window that links a chat's transcript into another instance. Chat titles are read only for display: never store, log, or report them. Never modify or delete a transcript; only create and remove links to it (a hard link for the transcript, a symbolic link for its subagent folder). Each extra instance has its own status line and hook commands (`--instance <name>`), snapshot `claude-usage-<name>.json`, chained-status-line config `statusline-<name>.json`, alert memory `claudeLimits.firedAlertKeys.<name>` and Keychain item (`ClaudeCredentials.keychainService(forConfigDirectory:)`); the main instance keeps the unsuffixed names.
- `Workdeck/Features/ClaudeCode/InstancesCompare/` — the Instances window: compares skills, MCP servers, plugins and instructions (`CLAUDE.md`, `rules/`) across instances (`InstanceSetupScanner`, `InstanceComparison`) and copies or installs what one lacks after a review (`SetupPlanner`, `SetupCopier`, `SetupReviewSheet`). Each cell's menu (`CellMenu`) also turns skills on and off through a reviewed `skillOverrides` change (`SkillOverrides`: `ClaudeSettingsFile` diff, ensure, backup, write) and removes items: skills and instruction files move to Replaced, plugins and MCP servers go through `claude` in Terminal (`uninstall --keep-data`). It never writes Claude Code's JSON files: plugins and MCP servers go through `claude` commands in Terminal. An MCP server's secrets live only in `MCPServerInfo.json` and `SetupAction`'s command: never displayed, logged or printed (`display` masks them; `description` and `customMirror` leave them out). A copy it replaces moves to `~/Library/Application Support/Workdeck/Replaced`. A skill's files are read only inside the skill folder, hidden entries left out, through `SkillFiles`, which the scanner's hash, Compare and the inspector's file list share.
- `Workdeck/Features/ClaudeCode/SettingsReview/` — the diff shown before Connect and Disconnect write a `settings.json`: connectors' `plannedConnect()` / `plannedDisconnect()` build a `SettingsChange` with the same transforms their writes use, without writing; confirming passes the reviewed change to `connect(reviewed:)` / `disconnect(reviewed:)`, which refuse a file that changed since. Secret-looking values are masked in the display only.
- `Workdeck/Features/Recap/` — the weekly recap for every agent: `RecapController` (app-level) records each `AgentSource`'s `recapSample` on every notch refresh through `RecapRecorder`; `RecapStore` keeps `recap.json` for 26 weeks (per day `seconds`, each project's real time across agents, and `agents`, each agent's own day; schema-1 days read as Claude Code's; counts, project and file names, session IDs and account labels only; never paths, prompts or contents). It shows last week's card on the first unlock of a week and owns the Statistics window (`StatisticsController`, `StatisticsWindow`, filtered by agent), whose activity grid (`ActivityGrid`, pure; `ActivityGridView`) shows the kept days. `RecapDemoScript` is its demo participant.
- `Workdeck/Features/Notes/` — Quick notes (quick notes spec): a tap of the right Option (or right Command, or a recorded combination) opens a panel from the notch; Return saves the line as a reminder in Apple Reminders, `#` picks a list with terminal-style Tab completion, a date sets the reminder, ⌘↩ hands the note to Claude Code or Codex in Terminal. `NotesController` (app-level, like `RecapController`) saves, lists and hands off over `RemindersStoring` (`EventKitRemindersStore`; tests use `FakeRemindersStore`), with `ShellCommand.claude`/`codex` (`--`, then the quoted prompt) and `TerminalAppLauncher`; `NotesSettings` remembers the agent and folder per list. `NotesShortcutMonitor` polls the key through `KeyStatePolling` (`CGEventSourceKeyState`, about 40 Hz, no Accessibility or Input Monitoring) and `ModifierTapDetector`, or registers a Carbon hot key (`HotKeyRegistering`). Pure: `NoteDraft`, `ListMatcher`, `NoteDateParser` (`NSDataDetector` plus two rules of its own), `FolderSuggestions`. `Panel/`: `NotesPanel` (a non-activating `NSPanel` on the screen with the pointer; `NotesPanelPresenter` hides the notch meanwhile with `NotchComposer.setSuspended`), `NotesPanelModel` and the views. `NotesCleanup` removes completed items of the lists used through Workdeck only after each one's line is written to `Notes Archive/YYYY-MM.md`. `NotesFolderSource` suggests folders from the Chats index and live sessions' `cwd` (titles dropped). `Demo/`: `NotesDemoScript` (pure) and `NotesDemo` (made-up lists, nothing saved). Reminders access is asked on the first save, never at launch. A note's text lives only in Reminders and the archive: never in `UserDefaults`, logs (`WorkdeckLog.notes` lines name the action and the list), Copy Diagnostics, the feedback attachment or `recap.json`; `UserDefaults` keeps only settings, list identifiers, the agent, instance and folder per list, and reminder identifiers with a hand-off's label and time.
- `Workdeck/Core/Updates/` — in-app updates (in-app updates spec): `UpdateController` (status for About and the popover row, the once-per-version notch alert `LimitsAlert.updateAvailable`, the remembered update in `UserDefaults`) over the `Updating` protocol; `SparkleUpdater` wraps Sparkle (gentle reminders: scheduled finds show Workdeck's alert and row, Install opens Sparkle's window); `Changelog` parses the bundled `CHANGELOG.md` (copied by the "Copy CHANGELOG" build phase) for the Release Notes window; `ReleaseNotesHTML` turns an appcast description into text, never rendered HTML. Sparkle's feed and public key are in `Config/Workdeck-Info.plist`; the private key is never in the repository. Tests use `InertUpdater`/fakes and never start Sparkle.
- `Workdeck/Core/Feedback/` — Send Feedback and Open on GitHub in Settings → About (feedback spec): `FeedbackMail` (address, body, `mailto:`, the route by the default mail app), `FeedbackSender` behind `FeedbackSystem` (Mail's compose service with the Copy Diagnostics report attached, else `mailto:` with the file shown in Finder; the clipboard as fallback). It only opens or copies; the user sends.
- `Workdeck/Core/Demo/` — `DemoMode` plays every registered `DemoParticipant`'s script on one clock while demo mode runs; nothing is persisted. `ClaudeCodeController` is a participant: its script (`Features/ClaudeCode/Demo/ClaudeCodeDemoScript`) is pure, and while the demo runs `refresh()` builds the notch from it and drops real alerts. `RecapController` is one too: `RecapDemoScript` gives it made-up days for both agents and the card for the last ten seconds. `NotesDemo` plays `NotesDemoScript` in the quick notes panel. A new tool adds its own script and conforms.
- `Workdeck/Features/Codex/` — the Codex tool, an `AgentSource`: `CodexLimitsSource` reads `rate_limits` from `token_count` lines of `~/.codex/sessions` (FSEvents for new files, plus a check of the five most recent files' dates on its minute tick: Codex appends to a session file it keeps open, and FSEvents reports no event for that; a 256 KB tail; no other line is decoded) and asks `codex app-server` (`account/rateLimits/read`) at launch, on popover open at most once a minute and on refresh. Never read `~/.codex/auth.json`. Fired alerts live in `codexLimits.firedAlertKeys`. `Sessions/`: `CodexHooksConnector` edits `~/.codex/hooks.json` (same shape as Claude's settings hooks, reviewed like them); `workdeck-hook --agent codex` writes to `sessions-codex/` and keeps the `codex` ancestor PID; a `ClaudeSessionStore` with `agent: .codex` and `oneSessionPerProcess: false` (Codex's app-server runs every chat of a window).
- `ClaudeUsage/` — compiled into the app and `WorkdeckStatusLine` (not the privileged helper): usage model, parser, snapshot file, chained command. Everything here is `nonisolated`. The snapshot carries the instance's `oauthAccount.accountUuid` (`ClaudeAccountFile`) and each session's last report by `session_id`, so stale sessions and another account's data are told apart.
- `Workdeck/Features/ClaudeCode/Limits/UsageAPI/` — opt-in poller for the undocumented `api.anthropic.com/api/oauth/usage` endpoint using Claude Code's Keychain token. Never refresh, persist, or log the token; keep it out of error text. It writes through the same snapshot file and merge as the status line. The token is read by running `/usr/bin/security`, which stays in the Keychain item's partition list; do not switch to `SecItemCopyMatching`, which asks for the login password after every Claude Code token refresh.
- `WorkdeckTests/Screenshots/` — `ScreenshotTests` renders the notch, popover, Statistics, Chats and the quick notes panel from demo data and made-up fixtures in temporary folders through an offscreen window (`ScreenshotRenderer`); it does nothing unless `make screenshots` sets `TEST_RUNNER_WORKDECK_SCREENSHOTS=1`. Windows render in a real titled offscreen window (`writeWindow`: title bar, toolbar, corners, shadow); the popover hangs from a drawn piece of the menu bar (`PopoverScene`). While rendering, `ActiveAppearance` makes the app report itself active and pins the accent to blue, so frames and switches draw in color. It also writes `notch-hover-animated.png` and `notch-alert-animated.png` (APNG, notch animations spec): `NotchAnimationTimeline` gives the frames, `writeAnimation` records them live in one window, `APNGWriter` stores each frame's changed rectangle.
- `WorkdeckTests/` — also compiles `WorkdeckHelper/` sources except `main.swift`, `HelperService.swift`, and `HelperListenerDelegate.swift` (exception set in `project.pbxproj`). Fakes live in `WorkdeckTests/Fakes/`.
- Source folders are Xcode file-system-synchronized groups: new files are picked up automatically. Do not edit `project.pbxproj` to add source files.

## Conventions

- Swift 6 language mode with strict concurrency. Pure value types, and anything called from XPC, IOKit, or other background callbacks, must be explicitly `nonisolated` or `@Sendable`.
- SwiftUI with native controls, system fonts, colors, and SF Symbols; follow the Apple Human Interface Guidelines; keep the UI minimal.
- English only: UI strings, code comments, documentation, commit messages.
- Finishing a feature or a user-visible fix adds a line for colleagues under `## Unreleased` in `CHANGELOG.md` (`### New`, `### Improved` or `### Fixed`; what changed for them, short, no internals), in the same commit. The app bundles the file for its Release Notes window.
- No third-party dependencies without discussing it first. Agreed exceptions: DynamicNotchKit (MIT, SPM, "Up to Next Minor" from 1.1.0) for the notch UI, Sparkle (MIT, SPM, "Up to Next Minor" from 2.10.1) for in-app updates, and the `oxipng` command-line tool (MIT, Homebrew, development only) that `make screenshots` runs on the notch animations.
- A change to how the notch, the popover, Statistics, Chats or the quick notes panel look ends with `make screenshots` and the updated images in the same commit; `docs/media/screenshots/` holds generated files only. `notch-expanded.png` changes slightly on every run (the session spinner follows the real clock): commit it only when the notch really looks different.
- Wrap system services (IOKit, `SMAppService`, XPC) behind protocols so controllers can be tested with fakes.

## Helper Rules

- Keep the helper minimal. Do not add XPC methods without an explicit security review.
- Never execute arbitrary commands or accept paths or arguments from the client.
- Every code path that disables sleep must have a matching restore path: normal quit, client crash or disconnect, helper restart, and reboot.
- The code-signing requirements and team ID live in `Shared/HelperConstants.swift`.
- The helper records its executable's path and inode at start (`ReplacementWatch`); a connection that finds another file there makes it refuse and leave as on SIGTERM (hand over or restore, then exit), so launchd starts the new build after an update. It never decides that from anything a client sends.

## Documentation Layout

- `specs/` design specs, `plans/` implementation plans, `docs/` other documentation (`docs/releasing.md`: cutting a release, CI secrets), `README.md`, `CLAUDE.md`, `CHANGELOG.md` (release notes for colleagues) and `TODO.md` (ideas and deferred work) in the root.
- A change to the README's tagline or Features updates the matching text in `site/index.html` by hand; the install command is the same string in both (a test checks it).
- `README.md` is the short overview (features, install, setup, privacy); feature details live in `docs/claude-code.md`, `docs/codex.md`, `docs/quick-notes.md` and `docs/closed-lid-mode.md`, images in `docs/media/`. A user-visible change updates the matching docs page, and the README when it changes the overview.

## Git

- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/): `type(scope): description`.
  - Types: `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `style`, `build`, `ci`, `chore`, `revert`.
  - Scopes are the area touched: `lid`, `helper`, `notch`, `limits`, `usage-api`, `statusline`, `sessions`, `hooks`, `instances`, `chats`, `accounts`, `settings`, `popover`, `app`; omit the scope when a change spans many areas.
  - The header is at most 72 characters, imperative, lowercase after the colon, no trailing period. Details go in the body, wrapped at 72 characters, after a blank line.
  - A breaking change adds `!` after the type or scope and a `BREAKING CHANGE:` footer.
- No `Co-Authored-By` trailers and no mention of Claude or AI tools in commit messages or PR descriptions.

## Verification

- Root-level behavior (helper approval, lid close, crash and reboot recovery) cannot be unit tested; follow `docs/testing.md` after changing the helper, `HelperClient`, or `LidSleepController`.
